# Початкове завантаження повідомлень за три дні

Telegram Bot API не має методу читання попередньої історії групи. Невидані оновлення зберігаються в Telegram не довше 24 годин. Тому бот отримує нові повідомлення через webhook, а для початкових 72 годин потрібен одноразовий експорт Telegram Desktop.

1. Додайте реальний чат у довідник **Адмінпанель → Чати**. Укажіть його Telegram ID та, за потреби, Telegram ID бота-відправника. Чат має бути увімкнений.
2. У Telegram Desktop відкрийте цей чат, виберіть **Експортувати історію чату**, формат **JSON**. Потрібен файл `result.json` одного чату. Можна не експортувати медіа.
3. У мініпрограмі відкрийте **Адмінпанель → Завантажити історію чату за 3 дні**, оберіть цей чат і файл `result.json`. Повторіть для кожного чату.
4. Система бере лише повідомлення за останні 72 години на момент завантаження, сортує їх за часом, зіставляє червоні й зелені події та пропускає повтори за Telegram ID повідомлення. Завантаження не надсилає сповіщення про минулі події. Якщо є лише зелене повідомлення з тривалістю, початок відновлюється за тривалістю; червоне без зеленого позначається як непідтверджене завершення.

Експорт обробляється через захищену паролем адміністративну сесію. Файл не потрапляє до GitHub або налаштувань Azure; у SQL зберігаються лише повідомлення з маркерами алгоритмів за обраний період. Старий тестовий архів видаляється один раз під час запуску нової версії; налаштовані типи алгоритмів і тексти відповідей зберігаються.

Для нових повідомлень від іншого бота у групі потрібні Bot-to-Bot Communication Mode в @BotFather, права адміністратора для цього бота та вимкнений Group Privacy Mode. Після цього перевірте, що webhook приносить нове червоне повідомлення до реального чату. Джерела: [Telegram Bot API](https://core.telegram.org/bots/api), [Bot-to-Bot Communication](https://core.telegram.org/api/bots/bot-to-bot), [експорт Telegram Desktop](https://telegram.org/blog/export-and-more).
